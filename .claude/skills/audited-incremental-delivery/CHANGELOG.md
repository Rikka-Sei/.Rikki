# Changelog

## [2.0.0] - 2026-10-31

- 不兼容变更：实现、提交、合并和推送分别核对授权；未获提交授权时以已审计的工作区差异记录增量，不自动提交，也不阻止已授权的实现。
- 不兼容变更：移除技能内的私密会话附件及其依赖；上下文恢复和规则缺口调查改用当前项目已授权的最小证据，不另建会话备份。
- 从会话中的纠正提炼现场保护、现有进程复用、reviewer 只读职责、审计判据变更后重审、锁与身份生命周期规则，不保留原始项目标识或日志。
- 性能验证补充负载端与服务端的可比基线、完整轮次、阶段和恢复观察、负载端资源耗尽归因；验收阈值来自当前任务，不再固定套用历史样例。
- 补充观测开销与有界性、现行规格与历史快照的权威区分，以及稳定交付与探索研究的隔离。
- 增加可分发技能的隐私边界，检查隐藏、忽略、压缩和缓存文件；删除数据不自动授权改写版本历史。
- 增量记录模板同步加入操作授权、运行对象、工作区差异、审计判据和证据保留清理字段。
- 签名改为检测本地可用 GPG 私钥后通过 ask 选择是否签名；多密钥时确认密钥，签名失败不降级，不再固定关闭 GPG，也不把个人密钥写入通用规则。

## [1.1.0] - 2026-10-30

- 新增“原始需求透传与 reviewer 提问”：对抗性审计必须提供用户原话或 transcript 精确位置，标明本增量覆盖范围；reviewer 可就原始需求向主代理提问，问答必须有文件、行号、命令或提交哈希证据并记录；未解决差异计入阻断项。
- 交付循环第 8 步和自审清单加入原始需求检查；增量记录模板新增“用户原始需求”段。

## [1.0.0] - 2026-10-30

首个稳定版本。

- 建立增量交付循环：契约 → worktree → 基线 → 增量 → 验证 → 自审 → reviewer → 提交。
- 增加审计检查点、提交检查、worktree 规则、证据等级、状态三档。
- 增加插入询问与中断协议。
- 增加 `.RānaKaname/workspaces/<slug>/progress.md` 增量记录和 `rana_workspace.py` 解析脚本。
- 增加上下文恢复、证据新鲜度、停止条件和 gap-scout 规则。
- 与 `nLsyntax` 双向交叉触发：本 skill 在写报告/提交说明/skill 文档前检查术语；`nLsyntax` 在多步骤交付场景反向引用本 skill。
- 性能证据作为附录保留，不把 skill 限定在性能任务。
