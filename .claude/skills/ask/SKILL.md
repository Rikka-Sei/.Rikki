---
name: ask
description: Auto-interview before a non-trivial task. Surfaces every decision point as a dual-column decision map (recommended *** + discouraged), supports a quick-probe path for agent-guessed disliked items the user only corrects when wrong. After user's "够了/go" confirmation enters no-interrupt mode (agent picks safe reversible options, only checks back for irreversible or oversized decisions). User can always say "我没看懂" / "重说" / "加进去" / "暂停" to interrupt at any phase. Agent must follow up proactively whenever it suspects the user may not have understood. **决策点 N ≥ 1 时必须经 `ask` 工具 emit（带 `questions[]` 参数），不得在对话流以 markdown 列表替代**——markdown 不支持点选 / 必拍板 UI / 1-2 字回话，是反例（见 § HARD-RULE）。
---

# ask

自动访谈 skill。agent 在执行非平凡任务前自动调起，把所有需要拍板的点一次摆开（决策图：推荐 *** + 不希望 双栏），同时给出每项推荐默认。用户确认后进入免打扰模式：执行中 agent 选安全可回滚选项跳过，仅在"问题太大"或"破坏性不可逆"时回来问。核心原则：**做的准确比做的多更好**。

不在本 skill 范围：

- 多轮多主题设计访谈（→ `brainstorming`）
- 写 `CONTEXT/` / ADR（→ `knowledge`）
- 跨模块契约（→ `core-spec`）
- 实施计划（→ `writing-plans`）

## 设计原则

| 原则 | 含义 |
|---|---|
| **全部清晰收敛** | 任务开始前 agent 主动扫描全任务路径，列出所有需要拍板的点；执行中遇未预见的歧义才补问 |
| **反例 + 推荐双栏** | 每条决策点列"推荐（\*\*\*）"和"不希望"两栏——让用户能反向剔除或正向认可；不指定 = 走 `***` 推荐 |
| **探路 = 推测的不希望项** | agent 推测用户"不要的是 X"，列出推测依据；用户只纠正不对的 |
| **必追到明白** | agent 自检发现"用户可能没懂"时**必须追问**——不准装懂、不准跳过 |
| **推荐默认** | 每个决策点都推一项（`***` 标记），带一句**依据**；用户不回也走默认（除非"说了绝对不能默认"的项标记为 `🛑 必须拍板`） |
| **免打扰双确认** | 决策图给齐后 agent 主动问"够了 / 还有补充吗？"；用户说"够了"或"go"后进入免打扰模式 |
| **做的准确比做的多** | 拿不准的不猜，回来问；执行中默认走低破坏 / 可回滚选项 |

**渐进推进**：agent 不一次性大改；每次推进一小块；保留双线（任务/决策点）并发；用户回话简短（"我没看懂" / "重说" / "加进去"等）agent 主动接住。

**主动照顾**：agent 主动扫描上下文 + 主动推测 + 主动列快捷项 + 主动汇报；用户在任意时刻可用一句话打断 / 补充 / 重塑。

## 何时调起

### agent 自动调起（任务前扫描）

- 任务标题命中 [reference/triggers.md](reference/triggers.md) § 任务级触发词 表的任一条
- agent 推断任务涉及 2+ 个独立决策点
- 用户提交任务但未指定关键参数（密码 / 路径 / 版本 / 命名空间）

### 执行中补问（未预见歧义）

- agent 在执行路径上遇到任务前未列入决策图的新歧义
- 满足"问题太大"标准（见 [reference/format.md](reference/format.md) § 免打扰触发条件）才回来问
- 其他可推测项直接选安全选项执行，任务后**集中汇报 agent 自行决定的项**

### 用户显式

- "先别动手，把要问的问完"
- "给我列决策点"
- "决策图给我看看"

## 何时不调起

| 情况 | 改走 |
|---|---|
| 能用 grep / 工具独立解决的事实 | 直接查，不问 |
| 任务非常简单（≤ 1 个独立决策点） | 直接做，不问 |
| agent 自己能拿主意（信心 ≥ ⭐⭐⭐，依据充分） | 直接做，不问 |
| agent 内部自检（"我给几星？" / "我该不该问？"） | **永远不**进决策图 |
| 仅是术语漂移 | `knowledge` 写 ADR |
| 涉及多主题需要分章节设计 | `brainstorming`（同 `brainstorming` 多轮访谈） |
| 用户明确"别问了，开干" | 跳过 ask 直接执行（仍写"零决策点声明"） |

## 决策图格式

> ⚠️ **本节是概念示意**，**不是 emit 形态**。ask 决策图必须经 `ask` 工具 emit（见 § HARD-RULE）；完整 emit 字段定义见 [reference/format.md](reference/format.md) § 决策图 emit 通道。

ask 决策图是**双栏对照**：每条决策点 = 推荐项 + 不希望项。完整定义见 [reference/format.md](reference/format.md) § 决策图。

```markdown
## 决策图：{任务名}（概念示意，不是 emit 形态）

agent 主动扫到 N 个决策点。**最多 8 条**；超出 → 见 § 超限处理。

### 必拍板

#### Q1 - {问题标题}
{问题正文}

推荐（***）：
1. {推荐项 1} —— {依据：仓库惯例 / spec 条款 / 路径成本 / 反例风险}
2. {推荐项 2} —— {依据}

不希望：
3. {忌讳 1} —— {为什么这是忌讳}
4. {忌讳 2} —— {为什么这是忌讳}

#### Q2 - {标题}
...

### 探路（agent 推测的不希望项）

- 我猜用户不想要的是：{一句话}（依据：{仓库惯例 / spec}）
- 我猜用户不想要的是：{一句话}（依据：{路径成本}）
- ...

### 子任务拆分建议（如果 N > 8）

- 子任务 1：{范围}，决策点 {N1} 条
- 子任务 2：{范围}，决策点 {N2} 条
- 跨子任务依赖：{X 必须在 Y 之后}

---

可用回话（1-2 字）：
- **够了 / go** → 进入免打扰
- **我没看懂** → 拆词解释
- **重说** → 重新生成决策图
- **加进去 X** → 补决策点
- **改问题** → 重新扫描
- **拆** → 拆子任务
- **暂停** → 立即停手
```

### 标签

- `🛑 必须拍板`：无合理默认 / 不可逆 / 影响跨任务 / agent 没把握。agent 不代用户拍
- `可默认`：有合理默认；不答按 `***` 推荐项走
- `推荐指数`：1-5 星，agent 推断的推荐强度（**可填可不填**，用户说"去掉"则去掉）
- `***`：推荐项最强标记，用户"不指定"行为默认走此项

### 双栏规则

- **推荐（\*\*\*）栏**：agent 强推的若干项，每项必带依据（仓库惯例 / spec 条款 / 路径成本 / 反例风险）
- **不希望栏**：agent 推测用户忌讳的若干项，每项必带"为什么这是忌讳"
- 双方数量不固定——agent 推测用户有几个忌讳就列几个
- `***` 项必须在推荐栏出现——确保用户"不指定"时有默认走

### 必追到明白（关键规则）

agent 在以下情形**必须**追问（不准装懂）：

- agent 自己**不确定**当前决策图对用户够不够清楚
- agent 自己**不确定**某项推荐依据是否站得住
- agent 推测的"不希望"项 agent 自己信心 < ⭐⭐⭐

agent 自检"用户可能没懂" → agent 主动追：

```markdown
[ask] 主动追问：{问题} → {我不懂的点 / 我的依据是否站得住}
```

用户回 "我没看懂" → 拆词解释：把该项**指向不明**换为较短的话 + 具体例子**重说**，不重新生成决策图本身。重说后再次询问："现在看懂了吗？或要重说整张决策图？"

## 调起后流程

```
任务到达
   ↓
agent 扫描全任务路径
   ↓
识别决策点（按 [reference/triggers.md](reference/triggers.md) § 决策点识别）
   ↓
生成决策图（每条 Q = 推荐 *** + 不希望 双栏；探路 = agent 推测用户不希望项）
   ↓
agent 自检"用户可能没懂"？→ 主动追（[ask] 主动追问）
   ↓
[如果 N > 8] 建议拆子任务，等用户回
   ↓
用户审阅决策图
   ↓
用户回 "够了" / "go" / "按你说的来" / 具体答复
   ↓
[进入免打扰模式] agent 执行
   ↓
执行中遇未预见歧义？
   ├─ 满足"问题太大"标准 → 回来问（出小型决策图，1-3 项）
   ├─ 不可推测安全选项 → agent 自己选 + 任务后集中汇报
   └─ 看到"用户可能没懂" → 再追
   ↓
任务完成 → 输出 [ask] 汇报：{agent 自行决定的项 + 用户拍板的项 + 完成度}
```

## 用户反馈快捷项

> 覆盖全阶段：决策图给齐前 / 用户拍板中 / 免打扰执行中 / 任务后汇报后。

ask 在任何阶段（决策图给齐前 / 用户拍板中 / 免打扰执行中 / 任务后汇报后）都要能接住以下用户回话：

| 用户回话 | 含义 | agent 行动 |
|---|---|---|
| "我没看懂" / "???" / "?" | 当前内容（决策点 / 选项 / 汇报）有歧义 | 拆词解释：把当前问题用更简单的话重说一遍，必要时举例；不改决策图本身 |
| "重说" / "再问一次" | agent 措辞不当导致歧义 | 重新生成决策图（保留必拍板项，重写探路项措辞） |
| "怎么问" / "什么不能问" | 用户想知道 ask 边界 | 引出 SKILL.md § 何时不调起 |
| "加进去" / "你漏了 X" / "补一项" | 决策图漏了用户认为必须的项 | 立即把 X 加到决策图（升格为 `🛑` 或探路，按 § 必拍板 vs 探路判据） |
| "改问题" / "问的不是这个" | 整个问题方向不对 | agent 重新扫描任务路径，重生成决策图 |
| "暂停" / "等一下" / "停" | 暂缓 | 立即停手，等用户回；不退决策图、不重启 |
| "拆子任务" / "拆" / "并行走" | 决策图超限或用户主动要拆 | 按 [reference/format.md](reference/format.md) § 超限处理 拆 |
| "跳过 X" / "X 走默认" / "X 不重要" | 某项用户授权 agent 自行决定 | 该项从决策图移除（任务后汇报里标"用户授权默认"） |
| "加我刚说的" / "加上 Y" / "还有 Z" | 用户补充决策点 | 同"加进去" |

agent 在每次出决策图 / 出选项 / 出汇报时，**显式列出可用的快捷项**（不必逐字列出全部，但至少给一句"如需 X，回 Z"），让用户不用自己想怎么回。详见 [reference/format.md](reference/format.md) § 用户反馈快捷项。

## HARD-RULE：决策图必须经 ask 工具 emit

> **决策点 N ≥ 1 时，agent 必须通过 `ask` 工具（带 `questions[]` 参数）emit 决策图；不得在对话流中以 markdown 列表替代。**

### 语义层定位

HARD-RULE 约束的是决策图的 **emit 形态**（怎么 emit），不约束：

- § 设计原则「渐进推进」（一次推进多少块）—— 是 **节奏**，与 emit 形态正交
- § 设计原则「免打扰双确认」（用户"够了"后 agent 选安全项不回头问）—— 是 **收敛时机**，与 emit 形态正交
- § 调起后流程里"执行中遇未预见歧义 → 出小型决策图" —— 仍是 ask 工具 emit，不是 markdown

### 原因

- markdown 列表**不支持**点选 / 勾选 / 单选 / 多选——用户必须回"Q1 选 A"等长串，违背"用户回话简短 1-2 字"
- markdown 列表**没有**必拍板项（`🛑`）UI 渲染——必拍板项的"agent 不替用户拍"语义丢失
- markdown 列表**无法**承载"已定 vs 待定"区分——所有项都长得一样，用户认知过载
- 示例：若 agent 用 markdown 列表列出多项待决问题，用户可能需要逐条理解并回复，增加认知负担；因此决策图必须通过支持交互选择的工具 emit。

ask 工具的 `questions[]` 参数是决策图的**唯一合法 emit 通道**。即便对话上下文已抹掉决策图形态（如非交互页），也走 ask 工具，由 ask 工具交付"决策图上下文"。

### 反例

```markdown
## 决策图：{任务名}
#### Q1 - {标题}
推荐（***）：
1. {推荐项}
...
```

→ 错误。必须用 `ask({questions: [{...}]})` 工具。

如果脚本里禁用工具调用（极少数场景），agent 应在文本里贴"决策图 JSON"让用户审阅，**不要**贴 markdown 列表。

> 设计原则：用户回话简短（理想 1-2 个字），agent 主动接住，不让用户敲长句。

## 免打扰模式

进入条件：用户**显式**回应"够了" / "go" / "按你说的来"。无显式确认不进入免打扰。

执行规则：

1. **可推测项**：agent 选 [reference/format.md](reference/format.md) § 安全选项判据 中定义的"低破坏 / 可回滚"选项，**不回头问**
2. **不可逆操作**（如删文件、改 schema、提交）：agent **仍然回来问**（标记为 `🛑` 的语义延伸）
3. **任务中浮现的新歧义**：满足"问题太大"标准（影响 3+ 步后续 / 改动跨模块）→ 出小型决策图（1-3 项）回来问
4. **任务后汇报**：列出 agent 在免打扰期间自行决定的 5-10 项（带"如不认可可回滚"标签）

退出条件：用户主动说"暂停" / "等一下" / 出现硬阻塞。

详细规则与示例见 [reference/format.md](reference/format.md) § 免打扰。

## 超限处理（> 8 条决策点）

agent 主动提示"拆子任务"并贴拆法，**不等用户问**：

```markdown
⚠️ 决策点 N = {N}，超过 8 条上限。

agent 建议拆为子任务：

- **子任务 1**：{范围}（决策点 {N1} 条）
- **子任务 2**：{范围}（决策点 {N2} 条）
- ...
- **跨子任务依赖**：{X → Y 顺序}

子任务 1 现在开始访谈，子任务 2 在 X 完成后开启。回 "拆" / "go 子任务 1" / "调整拆法"。
```

用户回 "拆" → 开始子任务 1 访谈；用户回 "go 子任务 1" → 同上；用户回 "调整拆法" → 重新生成拆法。

## 与其他 skill 的关系

- **`knowledge`**：ask 决策图本身不写仓；ask 推项被选完后，按 [knowledge 的触发链](../knowledge/reference/relationship.md) 判定是否留底
- **`brainstorming`**：ask 处理"任务前 + 执行中"的决策收敛；brainstorming 处理"多轮多主题设计访谈"。**不重叠**
- **`core-spec`**：ask 不写 spec；ask 决策图中"涉及跨模块契约"的项会主动推 → 走 brainstorming → core-spec
- **`writing-plans`**：ask 不写 plan；ask 决策图走完后调 writing-plans
- **`brainstorming`**：设计讨论需要多轮、多主题时由 `brainstorming` 承担；ask 只处理任务级决策收敛

## 反模式

| 错误 | 后果 | 正确 |
|---|---|---|
| 任务前不扫，进来就干 | 执行中频繁打断 | 任务前主动列决策图 |
| 决策图列 20+ 项不提示拆 | 用户认知过载 | N > 8 主动提示拆子任务 |
| **把决策图当汇报工具用** | 决策图本质被偷换为"agent 讲解方案" | 决策图本质是"等你拍板"，不是 agent 自我说明；agent 自我说明走任务正文 |
| **在对话流用 markdown 列表替代 ask 工具** | 用户无法点选 / 必拍板语义丢失 / 长串回话 / 精神负担 | 决策点 N ≥ 1 时**必须**用 `ask` 工具（见 § HARD-RULE） |
| **已定项混入决策图** | 用户被迫重复拍板已确认的项 | 决策图只列"待拍板"；已定项在决策图开头以"已定"声明列出，让用户识别哪些是真决策 |
| 把"事实查询"当决策点 | 用户得回答他能 grep 出来的 | 先 grep 后问（事实类问题不进决策图） |
| 拿"探路"问不可逆操作 | 误判导致不可恢复 | 不可逆操作必出双栏必拍板项，不走探路 |
| 免打扰期间跳过 `🛑 必须拍板` 项 | 越权代用户决定 | 免打扰中遇到 🛑 仍回头问 |
| 任务后不汇报 agent 自行决定 | 用户失去回滚窗口 | 任务后必汇报 + 提供回滚入口 |
| 把 brainstorming 当 ask 用 | 多主题访谈被压成决策图 | 多主题走 brainstorming；ask 仅任务级收敛 |
| 把 ask 当 knowledge 用 | 该留底的没留底 | 触发链判定留底时调 knowledge |
| **把用户当专家** | 让用户回答"agent 该给几星 / 该不该问" | agent 内部自检永远不进决策图 |
| **推荐项没依据** | 用户不信 agent 推项 | 每项推荐带"依据：{仓库惯例 / spec 条款 / 路径成本}" |
| **用"我猜不准"代替决策** | 推卸责任 | 没把握就标 `🛑`；有依据就自信推 |
| **让用户做 agent 该做的细节判断** | 加重用户负担 | agent 自己拿主意，只把方向感给用户 |

## 静态约束

- **决策点 N ≥ 1 时必须经 `ask` 工具 emit**（见 § HARD-RULE）
- 单任务决策图上限 8 条独立决策点
- 必拍板项（`🛑`）不设默认；agent 不替用户拍
- 探路项必须有"agent 推测 + 依据"才能算有效
- 推荐项必须有"依据"，不允许纯主观判断
- 免打扰模式仅在用户明确确认后进入；中途退出由用户触发
- 任务后汇报必出，不省略
