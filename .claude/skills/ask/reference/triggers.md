# reference/triggers.md

ask skill 的子参考：任务级触发词、决策点识别、安全选项判据的具体清单。

---

## § 任务级触发词（agent 调起 ask 的入口判据）

任务标题 / 任务描述命中以下任一，agent 在任务开始前主动调起 ask：

### 复杂度触发

- "设计" / "实现" / "做出来" / "落一个"——非平凡任务
- "重写" / "重构" / "迁移"——影响面大
- "完整" / "全套" / "全量"——范围待对齐
- "新加一个" / "新增" / "引入"——多决策点
- "接" / "集成" / "对接"——多模块

### 范围触发

- "X 到 Y" / "从 ... 到 ..."——边界未明
- "支持" / "兼容" / "包括"——范围矩阵
- "跨" / "整体" / "全局"——影响面大

### 决策点触发

- "再 / 又 / 还" 连续出现的"加上 X"——追加决策
- "和 Y 一起" / "顺便" / "同时"——决策点累加
- "以后" / "下次" / "未来"——长期影响

### 反例（不调起）

- "修" / "改一行" / "改个名字"——单点修改
- "看看" / "查一下" / "读一下"——只读
- "跑" / "测" / "build"——执行
- "等" / "停" / "重启"——运维

## § 决策点识别

agent 扫描任务路径时，按以下三类识别决策点：

### 1. 必须拍板（出双栏必拍板项）

任一条件为真：

- 不可逆操作（删 / 提交 / 部署 / 改 schema）
- 跨模块 / 跨任务
- 用户已说过"这个必须我决定"（`🛑`）
- 无合理默认
- 仓库无惯例

例：

- "队列项处理后的策略"（可能影响后续处理顺序）
- "数据库选型"（跨模块 + 影响面大）
- "API 路径前缀"（无合理默认）

### 2. 可推测（出探路）

任一条件为真：

- 有仓库惯例（grep `CONTEXT/` 与 `docs/specs/` 反查）
- 行业 / 生态惯例
- agent 信心 ≥ ⭐⭐⭐

例：

- "端口选 8000"（仓库惯例）
- "Go 还是 Rust"（看任务上下文）
- "commit message 用中文"（AGENTS.md 规定）

### 3. 跳过（不进决策图）

- 任务内部实现细节
- 注释 / 日志 / 调试
- 临时变量命名

## § 安全选项判据（免打扰期间 agent 自行选）

agent 选"不问"时必须满足：

| 判据 | 含义 |
|---|---|
| 可回滚 | git revert / 删文件 / 重新执行 ≤ 1 步回滚 |
| 低破坏 | 不影响线上 / 不破坏数据 / 不删正式文件 |
| 可预测 | 按现有 spec / 仓库惯例延伸 |
| 失败兜底 | 出错时有 fallback 路径或防御代码 |

不满足任一条 → 必回头问。

### 安全选项示例

- 临时文件命名（`tmp-foo.txt`）→ 安全
- 改一个函数的内部实现 + 单元测试 → 安全（git revert）
- 加新文件 + 不改现有 → 安全
- 删一个未使用的 import → 安全
- 改 schema 字段名 → **不安全**（必须问）
- 改生产数据库 → **不安全**（必须问）
- 改 spec 决策 ID → **不安全**（必须问）

## § 探路 ↔ 必拍板的动态转换

agent 探测过程中：

- 探路项被用户纠正 → 转必拍板（升格）
- 必拍板项被用户标"可默认" → 转探路
- 用户回"先 X 后 Y" → 拆子任务，X 优先访谈

转换时机：用户每次回应后 agent 重新评估。

---

## § 决策点与免打扰的边界

- **任务前**：必拍板 ≤ 8 条，探路 ≤ 5 条，超出 → 拆子任务
- **执行中**：免打扰期间，agent 选"安全选项"跳过，不回头问；任务后汇报
- **执行中**：免打扰期间，遇到"不安全"决策 → 必回头问（出 1-3 条小型决策图）
- **任务后**：汇报 agent 自行决定项（含回滚入口）

---

## § 调起后节奏控制

- 决策图给齐后必问"还有补充吗？"（双确认）
- 用户回"够了" / "go" 后**立即**进入免打扰，不追问
- 用户回"等一下" / "补充" → agent 等补决策
- 用户回"按你说的来" → 必拍板项走 agent 推荐默认，探路项走 agent 推测
- **兜底**：用户回"按你说的来"后，agent 在执行超过 3 步 / 跨模块前仍需简短告知"我将走 X / Y / Z 三步"，不闷头执行

## § 与其他 skill 触发词的协同

| 任务类型 | 触发 |
|---|---|
| 改 spec | 必调起 ask 决策图（spec-first） |
| 改 plan | 不调起（writing-plans 自带 spec-driven） |
| 写 CONTEXT/ | 调起 knowledge；决策点 ≤ 1 时不调 ask |
| 改 SKILL.md | 调起 ask 决策图（影响多 skill） |
| 修 bug | 不调起 ask；调 systematic-debugging |
| 实现新功能 | 必调起 ask 决策图 |

## § 自检

agent 调起 ask 前自检：

1. 任务是否触发复杂度 / 范围 / 决策点任一词条？
2. 决策点总数是否 ≥ 2？
3. 必拍板是否 ≤ 8？
4. 是否有"免打扰"用户表态历史（用户曾经说过"别问了"）？
5. **决策图是否走 `ask` 工具的 `questions[]` 参数 emit**？——markdown 列表是反例，必须改走 ask tool（见 SKILL.md § HARD-RULE 与 `format.md` § 决策图 emit 通道）

全过才调起。
