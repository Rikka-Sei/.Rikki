# 补丁类型语义参考

被 `SKILL.md` §补丁决策树引用。区分补丁类型时查阅。

## 三种补丁类型

### coldpatch（磁盘补丁）

- **修改对象**：二进制文件（.exe/.dll/.so）
- **持久性**：永久（重启进程/重载后仍生效）
- **停机**：需重启进程/重载
- **可见性**：静态分析可见（改了文件）
- **何时用**：需要永久修改、可承受停机、分发到多机、固件/嵌入式

### hotpatch（内存补丁）

- **修改对象**：运行时进程的代码段（内存）
- **持久性**：进程生命周期内（重启丢失）
- **停机**：零停机
- **可见性**：仅运行时（文件未改）
- **何时用**：生产不可停、运行时修复、瞬态行为控制

### runtime hooking

- **修改对象**：函数调用/事件拦截（不修改代码）
- **持久性**：hook 生命周期内
- **停机**：零停机
- **可见性**：实时拦截
- **何时用**：调试、监控、行为修改、不重编译测试

## 决策树

```
目标对象/行为持久存在？
├─ 是 → runtime 操作（读写字段、调函数）
└─ 否（瞬态/创建时决定）→ 改代码路径
    ├─ 需要永久 → coldpatch（磁盘补丁）
    └─ 只需运行时 → hotpatch（内存补丁）
```

**瞬态对象判定**：对象只在特定 UI 状态/时机存在（如菜单打开时）→ 瞬态。
瞬态对象的隐藏必须改代码路径（hotpatch 调用点），runtime-only 注定失败。

## 用户旨意混淆案例库

用户用宽泛词时，先区分具体类型再动手。

| 用户说 | 可能指 | 正确做法 |
|--------|-------|---------|
| "不要加补丁" | coldpatch? hotpatch? hook? | 先问是哪种，不要默认全删 |
| "不要加磁盘补丁" | coldpatch | ≠ 不要 hotpatch。内存补丁可保留 |
| "加个 hook" | runtime hooking? 还是 hotpatch? | 确认是拦截还是改代码 |
| "隐藏 X" | 改字段? 改代码? 改磁盘? | 先确认对象生命周期，再选类型 |

**反例**：用户说"不要加磁盘补丁"→ 误以为也不要内存补丁 → 撤销了正确的 hotpatch 工作。

**规则**：不懂先 web search 术语或先问，不要自作主张。补丁类型语义混淆会撤销正确工作或惹怒用户。
